## Day 2 ｜ 2026-09-16 ｜ 交付路线定案：**不上架**

**问题**：能不能像网页那样「买个服务器就上线使用」，不买域名、不做备案，只要不传播就行？只用于简历与毕设展示。

**核实结论（查官方文档 + 平台规则）**

1. 🚫 **「上架」这条路是堵死的**，且是两道锁而非一道：
   - **锁一：服务器域名不接受 IP**。小程序「服务器域名」必须填 **HTTPS 域名**，不支持 IP、不支持端口 ⇒ 现有 `http://8.133.255.202/api` 连配置入口都过不去。
   - **锁二：小程序自身也要 ICP 备案**。2023-09-04 起新增小程序**须完成备案才能上架**，未备案提交发布返回 `errcode 86369「小程序上架需先完成备案」`。个人主体可备案（上限 5 个），但**名称与服务内容不得涉前置审批领域**（含「新闻 / 网络文化 / 出版 / 游戏」等）——「游戏资讯」很容易撞上新闻类前置审批。
   - 叠加第三层：个人主体类目受限，且不能做论坛/社区，需把定位表述为「工具」类。
2. ⚠️ **「不传播就没事」这个假设不成立**。备案义务取决于「是否在境内提供互联网信息服务」，与传播范围无关；只是现实执行层面单机/演示用途通常不会被追究（阿里云已从技术上把未备案域名的 Host 头拦掉）。
3. ✅ **但「展示」根本不需要上架**。三条路都绕开备案：
   - **H5 版挂现有服务器**（最推荐）——手机浏览器打开 IP 即可，**完全不受小程序规则约束**。
   - **开发者工具 / 真机预览**——直连 IP；真机预览需在右上角菜单**打开调试**才跳过合法域名校验（官方文档口径）。
   - 体验版——**不需要小程序备案**，但请求仍走合法域名校验，因此仍需 HTTPS 已备案域名 ⇒ **不采用**。

**产出**

- `miniprogram/README.md` 新增「交付方式（已定：不走上架）」章节；「三条硬约束」扩为**四条**（第 4 条 = 不上架）。

**口径（重要）**

- 简历 / 答辩统一表述：**「完成小程序端开发，并通过 H5 版本部署上线」**。**不得写「小程序已上架」**——与既有的诚实原则一致。
