# YUMU 游戏助手 · 小程序方案设计 v1

> 撰写日期：2026-09-15 ｜ 定位：YUMU 游戏社区附带的微信小程序（课程大作业）
> 技术形态：uni-app（Vue3） ｜ 数据来源：现有 YUMU 社区后端（`http://8.133.255.202/api`）
> 配套原型：`prototype/index.html`（本目录的相对路径为 `../prototype/index.html`）

---

## 一、定位

社区本体是「论坛」，社交链路（私信 / 关注 / 通知 / 发帖 / 审核）是它的骨架。小程序**不做社区的第二入口**，而是切出一块**更轻、更工具化**的场景：

> **「我在玩什么 → 怎么过 → 最近更新了什么」**

因此砍掉全部社交互动与 UGC 发布，只保留**内容消费**。这样既避开了小程序端做社交的重活（登录态、实时通知、内容审核），又能把现有社区的**内容资产**（18 款游戏 / 133 篇帖子 / 六板块分类）直接用起来。

## 二、范围界定

| 做 | 不做（明确砍掉） |
|---|---|
| 首页（热门游戏 / 最新资讯 / 推荐攻略） | 私信、关注、粉丝 |
| 游戏库（搜索 / 平台类型筛选） | 实时通知、WebSocket 推送 |
| 游戏主页（攻略 + 资讯 双 Tab） | 发帖、回帖、富文本编辑器 |
| 内容详情（**攻略步骤卡** / 图片浏览） | 举报、审核、后台管理 |
| 资讯流（按分类筛选） | 用户主页、消息中心 |
| 搜索（帖子 / 游戏） | 签到、积分、等级体系 |
| 我的（本地收藏 / 浏览历史 / 可选登录） | — |

**可选保留（低成本、高感知）**：账号密码登录（复用现有 `/auth/login`）、点赞、收藏。

 └ 游戏主页 ← 从游戏库/首页进

| # | 页面 | 路径（建议） | 核心内容 |
|---|---|---|---|
| 1 | 首页 | `pages/index/index` | 搜索入口、热门游戏横滑、最新资讯、推荐攻略 |
| 2 | 游戏库 | `pages/games/games` | 游戏列表、关键词搜索、平台/类型筛选 |

## 四、接口映射表（全部为**现有接口**，后端零改动）

> ⚠️ **分页参数是 `current` 和 `size`，不是 `page`**。实测 `page=2` 会被静默忽略、恒返回第 1 页 —— 小程序做上拉加载时如果写错，会无限重复同一页。已实测确认：`current=2` 返回第 2 页。
> ⚠️ 响应统一为 `Result{code,message,data}`，**HTTP 状态码恒为 200**，成功与否看 `body.code`。分页体为 `PageResult{total,pages,current,size,records}`。

### 页面 → 接口 对应关系

| 页面 | 主要接口 |
|---|---|
| 首页 | `/games/hot` + `/posts?boardId=4`（资讯速递）+ `/posts?boardId=1&sort=hot`（推荐攻略） |
| 游戏库 | `/games`（分页 + 筛选） |
| 游戏主页 | `/games/{id}` + `/games/{id}/posts?boardId=1`（攻略）+ `?boardId=4`（资讯）+ `/active-users` |
| 内容详情 | `/posts/{id}` + `/posts/{id}/replies` + `/posts/{id}/tags` |
| 资讯 | `/posts?boardId=4` + `/announcements` |
| 我的 | `/auth/login`、`/auth/me`、`/posts/{id}/favorite` |

> 板块固定 id：1 攻略心得 / 2 游戏吐槽 / 3 组队大厅 / 4 资讯速递 / 5 二次创作 / 6 其他。**小程序只用到 1 和 4**。
> 📌 实测发现：线上 `GET /announcements` 与 `GET /picks/daily` 当前返回**空数组**，故资讯主线以 `/posts?boardId=4` 为**主数据源**，公告与精选作为增强（有数据时自动展示）。

## 五、技术方案

- **框架**：uni-app + Vue3（`<script setup>`）+ Vite
- **状态管理**：不引入 Pinia，用模块级 `reactive` 单例（小程序里够用且更轻）
- **请求层**：封装 `uni.request`，复刻现有 `frontend/src/api/request.js` 的行为 —— 注入 `Authorization` 头、判 `body.code !== 200` 弹提示、`401` 清登录态
- **富文本**：小程序不支持 `v-html`，用内置 `<rich-text>` 组件渲染。现有 `frontend/src/utils/richtext.js` 的 `renderRichText` 思路可迁移（转义 + 协议白名单），但输出节点结构需改成 `rich-text` 的 `nodes` 数组格式
- **图片**：后端返回的是 `/api/files/xxx` 相对路径，需拼成 `https://域名/api/files/xxx`；列表用缩略图（后端已自动生成 `_t` 后缀）
- **本地存储**：收藏、浏览历史走 `uni.setStorageSync`，不占用服务端

## 六、关键实现设计

### 6.1 攻略步骤卡（本项目最大的差异化亮点）

现有社区的攻略是**一整段长文**。小程序的阅读场景是"边玩边看"，需要**能定位到某一步**。做法：

**在前端解析正文，不改后端**。切分规则（按优先级）：
1. 显式序号：`第一步` / `1.` / `1、` / `Step 1` / `（1）`
2. 小标题：以 `##`、`【】`、`---` 包裹的短句
3. 空行分段兜底：段落 > 3 段时按段落成卡

产出结构：`[{index, title, desc}]`，渲染成序号圆点 + 标题 + 描述的卡片列表。若正文无法切分，则退化为普通正文渲染（不报错、不空屏）。

**这条设计的价值**：答辩时可以讲清"为什么不一上来改数据库"——现有内容已经存在，用**前端适配层**换取零数据迁移成本，同时给后续做结构化字段留出了演进路径。

### 6.2 其他要点

| 项 | 方案 |
|---|---|
| 登录态 | token 存 `uni.setStorageSync`；可选不做登录，收藏先本地 |
| 收藏双模式 | 未登录 → 本地；已登录 → 调 `/posts/{id}/favorite` 并本地留镜像 |
| 骨架屏 | 首屏用骨架块，避免白屏（现有 Web 端已有此模式） |
| 上拉加载 | 用 `onReachBottom` + `current` 自增；**务必用 `current`** |
| 分享 | `onShareAppMessage` 生成帖子/游戏卡片，成本极低、演示效果好 |
| 主题 | 延续社区深色 + YUMU 紫 `#7C5CFF` / 电竞青 `#19E3C2` |

## 七、平台限制与应对

> **结论先行：本小程序不走上架（发布）路线。** 上架需「HTTPS 已备案域名」+「小程序 ICP 备案」双前置，而现有条件只有 IP、未做任何备案，第 1 关就过不去。作业交付走 **H5 部署 + 真机预览/录屏**，见 §7.1。

### 7.1 交付路径（2026-09-16 定）

| 路径 | 需域名 / 备案？ | 说明 | 采用 |
|---|---|---|---|
| **H5 版挂现有服务器** | 否 | uni-app 编译出 H5 放到 `8.133.255.202`，手机浏览器打开即用；**不受小程序任何规则约束** | ✅ **主交付** |
| **开发者工具 / 真机预览** | 否 | 直连 `http://8.133.255.202/api`；手机预览需在右上角菜单**打开调试**才会跳过合法域名校验 | ✅ 答辩演示 |
| 体验版 | ⚠️ 需 HTTPS **已备案域名** | 上传代码→设体验版→加体验成员即可，**不需要小程序备案**，但请求仍走合法域名校验 | ❌ 不采用 |
| 正式发布（上架） | 🚫 域名备案 + 小程序 ICP 备案 + 过审 | 2023-09-04 起未备案不可上架（返回 `errcode 86369`） | ❌ 不采用 |

### 7.2 上架的四道关卡（记录备查，不实施）

| 关卡 | 要求 | 本项目 |
|---|---|---|
| 1. HTTPS 域名 | 服务器域名**必须 HTTPS 且为域名，不支持 IP、不支持端口** | ❌ 只有 IP |
| 2. 域名 ICP 备案 | 国内服务器绑域名须先备案，约 7–20 个工作日 | ❌ 未备案（阿里云已按 Host 头拦未备案域名） |
| 3. 小程序 ICP 备案 | 2023-09-04 起新增小程序须备案才能上架；**个人主体可备案**（上限 5 个），但名称与服务内容不得涉前置审批领域（含「新闻 / 网络文化 / 出版」等） | ⚠️ 「资讯」易触发新闻类前置审批 |
| 4. 类目 + 平台审核 | 个人主体类目受限，且不能做论坛/社区 | ⚠️ 需定位「工具」类，表述避开社区/资讯运营 |

> 📌 备案义务**不取决于是否对外传播**，而取决于「在境内提供互联网信息服务」。现实执行层面，仅本机/演示使用通常不会被追究（阿里云已从技术上拦掉了未备案域名），但**不能宣称「已上线运营」**——简历与答辩口径统一为「已完成开发并通过 H5 版本部署」。

### 7.3 其余限制

| 限制 | 影响 | 应对 |
|---|---|---|
| **个人主体不可用 `web-view`** | 无法内嵌 B 站/网页 | 视频改用自托管 mp4 + `video` 组件，或不做视频（详见 §八） |
| 项目**无任何视频代码** | 视频要从零做 | 视频降级为详情页的**可选模块**，不占主线 |
| 社区内容偏"讨论" | 像攻略的内容只有 27 篇 | 必要时补一批结构化攻略种子数据 |
| 小程序需 AppID | 无 AppID 无法真机预览 | 用**测试号**（无需主体，仅调试/预览用）或个人主体免费注册 |

## 八、关于视频（结论：**降级处理**）

想清楚这件事很重要，否则容易在一个点上翻车：

- ❌ **不能嵌 B 站/抖音** —— 个人主体用不了 `web-view`，这条最省事的路不存在。
- ⚠️ **`video` 组件播 mp4 可行，但同样受域名白名单限制** —— 开发期能演示，正式发布要配 HTTPS 域名。
- ✅ **推荐做法**：把视频当作**详情页里的一个可选模块**（标注"实战演示"），演示时用一段 5MB 以内的小 mp4 展示 `video` 组件的能力即可。**作品重心放在图文攻略的结构化上**（步骤卡），这样即便视频不播，功能依然完整、答辩依然讲得通。

## 十、待确认 / 风险

1. **老师是否要求"原生小程序"** —— 若强制原生（WXML/WXSS），则不能顺带产出 H5 版，需换成微信开发者工具原生工程。
2. ~~**是否需要正式发布**~~ —— **已决（2026-09-16）：不发布、不上架**。只做 H5 部署 + 真机预览演示，
   详见 §7.1。理由：上架需域名备案 + 小程序 ICP 备案双前置，成本高且「资讯」内容易触发新闻类前置审批。
3. **攻略内容量** —— 现有"攻略心得"板块仅 27 篇，且部分是讨论性质；演示够用，若要更饱满需补种子数据。
4. **登录的必要性** —— 不做登录则收藏只能本地（换设备丢失），但工作量最小；建议第一期不做，视时间追加。
